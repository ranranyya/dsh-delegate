# 1.4.0 等待阶段 token 对照报告

测量日期：2026-11-13。目的：验证外层短续等改成长等待后，当前 Codex 等待流程是否减少模型响应及其伴随 token。报告与发布结论由指挥端 Codex 撰写。

## 方法

两组在同一聊天中顺序运行，模型均为 `gpt-6.1-sol`。两组运行同一个 `scripts/verify-silent-wait.mjs --duration-seconds 45 --activity-seconds 5`，使用生产 `TaskMonitor` 与 `waitForTask`、真实墙钟和当前外层工具通道。执行活动由程序每 5 秒模拟，不调用 DSH 提供方模型，不改变安装设置。

- 短续等组：外层选择短 yield，返回仍运行的单元后，由 GPT 两次续接同一单元。
- 长等待组：外层允许等待 120 秒，程序保持同一次调用直到约 45 秒的任务交付。
- 只统计发出实验等待或续等工具调用的 GPT 响应；前期规划、程序审查、报告撰写及最终交付审查不混入本表。
- 从本机 `token_usage_record` 读取单次 `usage`，按 `response_id` 去重；不累加累计 `thread_token_usage`，缓存输入是输入的子集，推理 token 不重复加到总量。

## 实测结果

| 项目 | 短续等组 | 长等待组 | 减少比例 |
|---|---:|---:|---:|
| 等待程序实际时长 | 44,165 ms | 44,175 ms | 同时长对照 |
| GPT 响应数 | 3 | 1 | 66.67% |
| 外层中途交回 | 2 | 0 | 100% |
| 输入 token | 507,408 | 169,443 | 66.61% |
| 其中缓存输入 | 506,651 | 169,320 | 66.58% |
| 非缓存输入 | 757 | 123 | 83.75% |
| 输出 token | 477 | 291 | 38.99% |
| 输入＋输出 | 507,885 | 169,734 | **66.58%** |
| 序列化工具返回字节 | 530 | 394 | 25.66% |

两组等待程序均以 `ready` 返回，检查通过，均只产生一个任务业务结局。短续等组额外两次模型响应来自外层交回后的续接，不来自执行任务的需要判断事件。

## 如何理解

这次样本说明：当前客户端把正常执行包在一次长等待内，确实能省去中间续等的模型回合。本次减少主要来自不重复携带整段上下文；输入大部分已命中缓存，因此 **66.58% 不是费用或额度扣减比例**。

本实验只有每组一次，顺序固定，后组上下文会略增长，没有置信区间，也没有控制冷缓存差异。它验证等待机制，不能推出所有任务或完整开发成本固定减少同样百分比，更不能把 45 秒结果直接外推成 20 分钟实测费用。

过去骑砍任务的内容、上下文和执行结果不一致；它们用于定位短等待和重复读取问题，不作为本版因果节省率。本次将短时 token 对照与先前 20 分钟零中途唤醒的等待验收分开记录。

## 复核

本轮本地证据包含 `1.4.0-token-wait-benchmark.json`、`measure_wait_tokens.py` 及两份等待探针日志；保留逐响应用量和工具调用定位，不复制完整对话、执行者思考或凭据。正式 Release 提供脱敏的汇总 JSON 与探针日志；核算方式是 `(短组总量 - 长组总量) / 短组总量`。
