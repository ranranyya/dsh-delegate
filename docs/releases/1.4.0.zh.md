# DSH TaskBridge 1.4.0 更新说明

让 Claude Code 或 Codex 指挥 DSH 工作，在 DSH 插件中选择 API、执行模型和思考强度。1.4.0 重点改进静默等待、重复失败提醒和交付审查状态。

## 执行期间由程序观察，指挥端按需介入

- 正常派工后使用 `delegate_wait({ taskId })`，省略短 `waitSeconds`。程序在内部持续观察，不把每次心跳交给 GPT，也不反复搬运中间对话和代码差异。
- Codex 集成规则明确要求使用客户端支持的长等待；外层提前交回仍在运行的执行单元时，续接同一个单元，不重新派工、不另开等待、不把等待中断当作任务失败。
- 原有无活动监控保持默认 5／10 分钟：连续无新活动 5 分钟由程序自检，10 分钟才交给指挥端判断；真实输出、思考流和工具事件重新计时，连接心跳及页面刷新不重置计时。
- 权限申请、交付、失败、取消和中断及时返回。正常执行期间集中等待，交付后集中审查；修改意见通过 `continueFromTaskId` 续接原任务对话和执行工作区。
- 修正执行阶段显示：实际执行尚未开始时不提前显示执行中；失败后不保留执行阶段，晚到事件不覆盖审批或终态。

## 新增重复失败提醒

高级设置增加“重复失败提醒（次）”，默认 3 次，可设 0 关闭，允许 0–20 的整数。同一工具、同一操作连续出现相同的结构化失败时提醒指挥端一次；成功或失败身份变化后重新计数。

提醒沿用紧凑的 `attention` 返回，不自动取消、换模型、重派或延长时限。权限请求和执行结局优先。普通输出出现 error 字样、长时间思考、运行长测试或没有文件改动，不会被当作重复工具失败。任务详情和历史保留有界提醒，不记录原始参数、错误正文或思考内容。

## 宿主审查结论写回任务记录

新增 `delegate_review`，由指挥端读取结果、检查改动和验证证据后，明确记录“审查通过”或“需要修正”，任务页同步显示。执行者交付本身仍然不等于通过审查。

审查记录只针对一个已交付任务，不授予工具权限，不修改模型、开关或隔离方式，也不会合并工作树。需要修正时续接原任务；已有决定保留在原记录中。底层执行状态继续兼容旧客户端，旧历史记录不批量补写虚构的通过结论。

## Codex 集成和配置兼容

- 更新包内 `dsh-taskbridge` 智能体规则，支持识别未修改的已发布 1.3.2 模板，在插件加载时刷新已有托管集成。
- 新安装仍由设置页“安装／更新 TaskBridge 智能体”按钮创建智能体与 MCP；更新后必要时重新加载 Codex，让客户端读取新规则和工具目录。
- 用户自行修改过的智能体文件保留，并显示需要处理的状态；无需删除整个 Codex 配置目录。
- 旧设置缺少重复失败字段时采用默认值；表单空值、越界和小数给出明确校验。修复监控设置保存和旧历史字段的兼容问题。

## 安装与更新

在 DSH 插件管理中更新 `dsh-taskbridge`，或添加 `dsh-taskbridge@1.4.0`，也可使用本 Release 的 `dsh-taskbridge-1.4.0.tgz`。区域镜像尚未同步时改选 npm 官方源。

同包更新后确认插件加载成功，在 Codex 集成页查看智能体及 MCP 状态；旧客户端可能需要重新加载。首次安装点击集成安装按钮；有冲突时使用插件提示的安装／修复操作。从旧包名迁移仍按现有迁移指南处理，不同时启用新旧插件。

## 等待阶段 token 实测

在同一聊天、同一 `gpt-6.1-sol` 模型中，对同一个生产等待程序各运行约 45 秒：短外层等待产生 3 次 GPT 响应，长等待产生 1 次。按实际逐响应用量记录，输入加输出从 507,885 降至 169,734 token，**这次等待样本减少 66.58%**；其中非缓存输入从 757 降至 123。

这是单轮、短时、先短后长的等待通道对照，执行活动由程序模拟。它不是整个开发任务、真实模型执行或账单的节省比例，不能宣传成所有任务固定节省 66.58%。完整口径见[测量报告](1.4.0-token-benchmark.zh.md)。此前真实墙钟 20 分 2 秒的正常活动模拟等待，已验证中途零 GPT 续等；真实 DSH 任务也独立验证了多分钟等待及权限申请返回。

## 发布前验证

- 最终全量回归：**1,222 项通过，0 失败、0 跳过**；客户端构建及构建一致性检查通过。
- 宿主审查专项覆盖 20 项，包括通过／要求修正、落盘和重载、重复请求、并发写入、持久化失败回滚、关闭派工开关后的结论记录，以及界面标签一致性。
- 包内实测补齐了审查路由的中间转发映射，并新增真实转发客户端的路由与载荷回归，避免只测工具和服务端而遗漏中间连接。
- 安装包另做隔离安装、真实 stdio 握手和 8 个工具目录检查；临时 Codex 目录验证 1.3.2 托管规则升级、等待超时配置与自定义智能体保留。审查闭环使用安装包实现、真实本机 HTTP 与历史文件，原生执行服务和 Git 证据使用测试夹具，不调用提供方模型。
- 正式 Desktop 配置不由本次测试修改。用户在插件管理中更新并重新加载 Codex 后，才会在实际使用环境启用新的工具和规则。

## 边界

插件不控制所有客户端的工具时限，单次 MCP 等待最多 60 分钟；客户端提前返回或达到等待上限时，仍需续接同一任务。重复失败检测不代替交付质量审查。本版没有新增 CLI 执行通道、Claude Code 一键安装或普遍适用的原生 `@` 能力。
