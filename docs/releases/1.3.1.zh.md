## 功能与版本变化

让 Claude Code 或 Codex 指挥 DSH 完成任务；指挥端负责规划和审查，DSH 按插件设置执行。在 DSH 设置页选择已接入的 API 提供方、执行模型及模型支持的思考强度，并配置权限审批、超时、并发、隔离和可选的额外模型审查。

| 版本 | 主要内容 |
| --- | --- |
| 1.2.0 | 修复静默等待被中断的返回语义，增加独立状态／取消控制通道，修复既有 Codex 集成升级遗漏。 |
| 1.3.0 | 采用 TaskDispatch 名称，增加中英文介绍、图标、迁移兼容和固定 Git 提交的自定义索引；只通过 GitHub 分发，npm 未接受该名称。 |
| 1.3.1 | 最终统一为 TaskBridge，正式增加 npm 分发，兼容本项目旧仓库身份与已发布的 1.3.0 agent 模板。 |

1.3.1 的核心派工、等待、权限决定、集中审查和同任务续接流程沿用 1.2.0。另修正控制程序向底层传入测试依赖的方式，使测试使用隔离的 mock 客户端，避免误连真实 DSH；默认 CLI 使用方式不变。

Codex 提供设置页的安装／修复按钮。Claude Code 通过标准 stdio MCP 手动连接，参见 [接入说明](../claude-code.md)。本版没有新增 Claude Code 一键安装按钮或独立的上下文窗口设置。

## 安装与旧包迁移

新安装：在 DSH Desktop 的 **插件 → 添加插件** 中输入：

```text
dsh-taskbridge@1.3.1
```

希望在“发现”中搜索时，需要添加本项目的自定义索引。**这不等于已收录官方默认插件市场。** npm 分发已可用，但搜索入口和更新按钮的行为取决于 DSH 客户端版本。

从本项目旧版升级时：

1. 完成或停止旧任务，关闭调用开关。
2. 停用并卸载本项目旧的 `dsh-delegate` 或 `dsh-taskdispatch` 包，保留 `<DSH_HOME>/data/dsh-delegate`。
3. 安装 `dsh-taskbridge@1.3.1`，按需要启用、确认设置。
4. 在 Codex 集成页点击安装／更新或修复 MCP，重新加载 Codex。

不要同时启用新旧包，也不要安装 npm 上他人的同名历史项目。旧的 `delegate_*` 工具、`DSH_DELEGATE_*` 环境变量、数据目录、CLI 名称、`agents/dsh-delegate.toml` 和 `mcp_servers.dsh-delegate` 技术标识保留兼容，详见 [升级说明](../taskbridge-upgrade.md)。迁移不会自动打开调用开关。

- 本轮没有重新调用冷却中的 workbuddy 模型，没有真实模型端到端重跑。
- 没有在用户正式 Desktop profile 中执行完整安装、迁移、重启和搜索操作；隔离测试不替代这项验收。
- Claude Code 仍为手动 MCP 接入，尚无一键按钮或真实 Claude Code 客户端验收。
- 兼容范围仍为插件声明的四个 DSH 预发布版本及 Node.js 24+，不承诺其他宿主版本可加载。
- 不承诺所有客户端原生 `@`、完全零唤醒、固定 token 节省比例或所有 DSH 版本自动更新。
- 本轮未修改用户正式 DSH、Codex、Claude 配置、全局 npm 或账户安全设置；npm 本人验证由用户完成。
