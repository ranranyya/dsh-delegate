# DSH TaskBridge 1.3.2 更新说明

让 Claude Code 或 Codex 指挥 DSH 完成任务，在 DSH 插件中配置 API、执行模型和思考强度。

本次小版本完成两个界面上的名称同步，并修复旧包卸载后的 Codex 连接迁移。

## 改动

- **Codex 智能体改为 `dsh-taskbridge`**。安装按钮、模板和派工规则同步更新。未修改的已发布旧 `agents/dsh-delegate.toml` 会迁移为 `agents/dsh-taskbridge.toml` 并清除旧文件；用户修改过的文件保留。MCP 的内部服务标识和 `delegate_*` 工具继续兼容。
- **新工作区按工作内容命名**。例如“制作潘德 G 版装备表”“修复授权界面”，不再仅显示工作树的 `task-UUID`。派工方提交简短 `title`；旧客户端未提供时从任务目标中提取。重名会加短标识。续接同一任务、使用已有工作区时保留原名称，不批量修改历史记录。命名不调用额外模型，也不修改磁盘路径。
- **修复卸载旧包后 MCP 仍指向旧目录的问题**。通过设置页显式安装或修复时，可迁移与当前插件处于同一 `node_modules` 的已卸载旧包标准路径。原配置仍须带插件托管标记；其他路径和自定义包装器保留。启动自检不接管搬家路径。

模型、API、思考强度仍由 DSH 插件设置决定。总开关、静默等待、权限审批和交付后集中审查沿用现有流程。

## 安装与更新

在 DSH 的“添加插件”中使用 `dsh-taskbridge@1.3.2`，或选择 GitHub Release 的 `dsh-taskbridge-1.3.2.tgz`。从 TaskBridge 1.3.1 升级属于同包更新；从更早包名迁移请阅读[升级说明](../taskbridge-upgrade.md)。

更新后在插件的 Codex 集成页点击“安装 / 更新 TaskBridge 智能体”，然后重新加载 Codex。客户端提供智能体选择时，选择 `dsh-taskbridge`。已安装且未修改的旧智能体也会在插件启动时自动迁移；插件不会覆盖自定义文件。

自定义索引继续使用 <https://ranranyya.github.io/dsh-taskbridge/index.json>，不是官方默认市场收录。

## 验证边界

Windows + Node 24 上 **1155 项自动测试全部通过**，前端构建一致性通过。测试覆盖标题贯通 MCP、HTTP、任务引擎和 Workspace 命名，以及旧模板迁移、重复安装和自定义文件保留。

正式安装包的隔离安装通过；真实 stdio MCP 初始化返回 `1.3.2`，7 个工具齐全并接受 `title`。实际 1.3.1 旧模板自动更名、清理重复智能体、启动不接管搬家 MCP 路径、显式修复已卸载旧包路径、重复安装幂等均通过安装包验收。

真实 Desktop 更新、Codex 客户端重新加载后的名称显示，以及真实模型调用仍需在用户环境确认；隔离测试不等同于这些客户端操作已经完成。不承诺所有客户端原生 `@`、零唤醒或固定 token 节省比例。
